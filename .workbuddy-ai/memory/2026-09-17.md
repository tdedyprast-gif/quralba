## Fix: Frontend tidak bisa diakses di browser
- User membuka `http://localhost:8080` (port backend) bukan `http://localhost:3000` (port frontend)
- Masalah lebih dalam: VITE_API_URL=http://localhost:8080 di-bake ke JS bundle, jadi kalau diakses dari device lain API call gagal
- Solusi: Nginx reverse proxy di frontend container — /api dan /ws di-proxy ke backend:8080
- Update `frontend/nginx.conf`: tambah location /api/ dan /ws/ proxy_pass ke backend
- Ubah `||` ke `??` di 4 file frontend (api.js, Penerima.jsx, QRScanner.jsx, Peta.jsx) supaya empty VITE_API_URL tidak fallback ke localhost:8080
- Set VITE_API_URL= (kosong) di .env — frontend pakai relative URL, semua lewat Nginx
- Rebuild frontend container — verified: localhost:8080 tidak lagi ada di JS bundle, API proxy works via port 3000

## Tambahan: daftar akun editable + pilihan role lengkap (Validasi Akun)
- `handlers/admin.go` — tambah `allowedRoles` (admin/bendahara/pembagian/peserta/penerima) & `allowedStatus` (pending/active/rejected) sebagai validasi terpusat.
- Helper baru `ensurePesertaRecord()` / `ensurePenerimaRecord()` — idempotent: pakai tautan yang ada → pakai record dengan email/no_hp sama yang belum tertaut → baru buat baru. `ApproveUser` direfaktor memakai helper ini.
- Handler baru `CreateUser` (`POST /api/admin/users`) — admin membuat akun langsung, khususnya panitia (admin/bendahara/pembagian) yang tidak bisa self-register.

- `ListUsers` sekarang mengembalikan `peserta_id`/`penerima_id` + dukung filter `?role=`.
- Frontend `ValidasiUser.jsx` ditulis ulang: judul "Validasi & Kelola Akun", dropdown role inline di tabel (ganti langsung tersimpan), modal Edit (nama/email/hp/alamat/role/status), modal "+ Tambah Akun", filter status + filter role, kartu "Sebaran per Role".
- Label role di UI: admin = "Admin (Super User)", bendahara = "Panitia Bendahara", pembagian = "Panitia Distribusi (Pembagian)", peserta = "Peserta Qurban", penerima = "Penerima Daging". Dikelompokkan optgroup "Panitia" vs "Peserta / Penerima".
