### ⚠️ TEMUAN PENTING — Fiber v2 `Group("", middleware)` bocor antar route
`api.Group("", middleware.RequireRole(...))` **tidak** membuat scope middleware lokal. Di Fiber v2, `Group(prefix, handlers...)` memanggil `register(methodUse, parentPrefix+prefix, handlers...)`, jadi dengan prefix `""` ia mendaftarkan `Use("/api", mw)` di app. Middleware `Use` itu lalu berlaku untuk SEMUA route `/api` yang didaftarkan SESUDAHNYA, dan urutan eksekusi mengikuti urutan registrasi.
- Akibat nyata: menambahkan `api.Group("", RequireRole("peserta"))` di ATAS blok admin membuat `/api/admin/users` balas **403 "akses ditolak untuk role admin"**.
- Bug laten yang sudah lama ada: grup `bendahara` didaftarkan sebelum route `pembagian`, jadi middleware bendahara juga membayangi route pembagian (tertutupi karena keduanya mengizinkan `admin`).
- **Perbaikan**: seluruh route terproteksi di `cmd/main.go` sekarang pakai guard **per-route** — `api.Get("/paket", kasir, handlers.ListPaket)` dengan `kasir := middleware.RequireRole("admin","bendahara")` dan `dist := middleware.RequireRole("admin","pembagian")`. Tidak ada lagi `Group("")`. Urutan registrasi jadi tidak lagi menentukan keamanan.
- **Aturan ke depan**: JANGAN pakai `api.Group("", middleware...)` untuk guard role di proyek ini. Pakai middleware sebagai handler per-route.

## Lanjutan: perbaikan rantai landing → register → approve → record peserta
Audit lanjutan menemukan **dua bug nyata** di alur yang diminta user (pilih paket di landing → daftar → validasi admin):

1. **Kuota tidak ditegakkan saat approve.** `ensurePesertaRecord` mengambil harga paket tanpa mengecek `max_shohibul`. Dua orang yang mendaftar ke paket 1 slot sama-sama di-approve → `terisi 2/1` (over kuota).
2. **Paket pilihan pendaftar hilang** kalau sudah ada record peserta lama dengan email sama yang belum tertaut (dibuat manual panitia / hasil import). Fungsi mengembalikan `pid` record lama tanpa menerapkan `paketID` → peserta tidak dapat paket & tagihan 0 padahal sudah memilih di halaman pendaftaran.

### ⚠️ GOTCHA Postgres: `uuid <> ''` bikin query error diam-diam
Perbaikan pertama awalnya gagal: `SELECT COUNT(*) ... WHERE paket_id=$1 AND id<>$2` dengan `$2 = ''` → Postgres mencoba cast `''` ke `uuid` → error "invalid input syntax for type uuid". Karena error-nya di-`_ =` (diabaikan), `terisi` tetap 0 → kuota selalu dianggap tersedia. **Pelajaran**: kolom uuid JANGAN pernah dibandingkan dengan string kosong; dan jangan telan error query hitungan.
Perbaikan final: `paketHargaKuota()` memisah query (dengan/tanpa exclude) dan **fail closed** — kalau query hitung gagal, paket dianggap tidak tersedia.

### Perubahan
- `handlers/admin.go` — helper baru `paketHargaKuota(ctx, paketID, excludePesertaID) (harga, tersedia)`. `ensurePesertaRecord` sekarang mengembalikan `(pesertaID, paketPenuh, error)`: cek kuota sebelum memakai paket; kalau record lama belum punya paket → lengkapi dengan paket pilihan pendaftar + `recalcPeserta()`; kalau kuota penuh → `paketPenuh=true`. `ApproveUser` & `UpdateUser` mengembalikan `{"paket_penuh":true,"peringatan":"..."}`; `CreateUser` pakai `_` (paket selalu nil).
- `frontend/src/pages/ValidasiUser.jsx` — toast ⚠️ durasi 7 detik kalau `r.data.peringatan` ada, supaya admin tahu paket tidak jadi ditetapkan.
